# Gram Farm

Админ-бот управляет подключёнными Telegram-аккаунтами, плановыми командами и сохранёнными заказами: реакции, вступления/заявки, реферальные переходы и просмотры.

> Используйте только аккаунты и ресурсы, которыми вы вправе управлять. Массовая автоматизация может нарушать правила Telegram и привести к ограничениям. Встроенный карантин не гарантирует защиту аккаунтов.

## Установка

1. Установите Python 3.11 или новее.
2. Создайте Telegram-бота через `@BotFather`, получите `api_id` и `api_hash` на `my.telegram.org`.
3. Создайте окружение и конфигурацию:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

4. Заполните `.env`. Не меняйте `SESSION_SECRET` после добавления аккаунтов и не храните `.env` рядом с публичным репозиторием или резервной копией БД.
5. Запустите `python main.py`, затем отправьте управляющему боту `/start`.
6. До production прогоните `python -m unittest discover -s tests -v` и staging-тесты на отдельных аккаунтах.

Аккаунт можно добавить по номеру телефона или импортировать из ZIP с одной папкой
`tdata`. Для пакетного импорта положите до 100 отдельных tdata ZIP в один общий ZIP. Для импорта сначала отключите локальный пароль Telegram Desktop и полностью
закройте приложение. Архив ограничен 50 МБ, распакованные данные — 200 МБ; после
создания зашифрованной StringSession временные файлы удаляются.

## Надёжность и заказы

- Заказы сохраняются в SQLite до запуска. Прогресс каждого аккаунта фиксируется отдельно.
- Незавершённый заказ восстанавливается после перезапуска. RPC, прерванное ровно в момент рестарта, помечается ошибкой и не повторяется автоматически, чтобы не дублировать действие.
- Один аккаунт атомарно резервируется только одной операцией. Плановые циклы, ручной запуск и заказы не используют одну сессию одновременно.
- Заказ можно отменить. Уже начатое Telegram RPC завершается безопасно, оставшиеся аккаунты помечаются отменёнными.
- Итог: `Заказ #N выполнен. Получилось сделать X, ошибок — Y.` Детали каждого аккаунта хранятся в `order_items`.
- Задержка подписок и реферальных переходов применяется **между аккаунтами**. Значение ограничено диапазоном 0–1440 минут.
- Новая сессия не участвует ни в плановых циклах, ни в заказах первый час.

## Поддержка ссылок

- Посты: `https://t.me/channel/123`, `https://t.me/c/123/456` и ссылки на посты в темах, если аккаунт имеет доступ.
- Публичные каналы и супергруппы: вступление; приватные ссылки: вступление или подача заявки.
- Обычные пользователи не имеют механизма «подписки» в Telegram. Для ссылки на пользователя бот добавляет профиль в контакты и записывает именно такой результат.
- Реферальные боты: `?start=...`; предварительные ссылки могут вести в каналы, чаты или ботов.
- Все ссылки строго проверяются: принимаются только полные HTTP(S)-ссылки доменов `t.me` и `telegram.me`.

## Плановые циклы

- `FARM_ENABLED` и `STALL_ENABLED` включают соответствующие циклы.
- Новый аккаунт ждёт один час перед первым действием.
- Между плановыми аккаунтами выдерживается `BETWEEN_ACCOUNTS_SECONDS`.
- Бонусный цикл использует таймер из ответа бота, добавляет `BONUS_EXTRA_MINUTES`, а при отсутствии кнопки и таймера повторяет через `BONUS_FALLBACK_MINUTES`.
- При `FloodWait`, `PeerFlood` или деактивации аккаунт переводится в карантин и требует ручной проверки.
- Если указан `TARGET_BOT_USERNAME`, кнопки фермы и ларька принимаются только от этого бота. Без него принимаются кнопки только от bot-аккаунтов, поэтому для production параметр лучше заполнить.

## Выплаты

Автовыплаты включаются через `PAYOUT_ENABLED=true` (так указано в `.env.example`). В обзоре системы видно фактическое состояние. При включении сумма должна находиться между `PAYOUT_THRESHOLD` и `PAYOUT_MAX_AMOUNT`, ответ должен быть привязан к команде аккаунта, а источник фиксируется в уникальном `payout_ledger`, предотвращающем повторную отправку по одному сообщению. Сначала обязательно проверьте это на staging.

## Пул и служебный аккаунт

- Рабочий аккаунт назначается в самый свободный активный чат, если есть место. Отсутствие свободного чата больше не мешает добавить аккаунт для заказов.
- Служебный аккаунт исключён из пула и плановых/заказных действий, в том числе после перезапуска.
- Смена служебного аккаунта возвращает предыдущий в рабочий пул.
- Выдача админ-прав служебной сессией сериализована, чтобы одна сессия не использовалась параллельно.

## Хранение и эксплуатация

- Сессии зашифрованы Fernet в `data/farm.db`; `.gitignore` исключает `.env`, БД, WAL, session-файлы и кэши.
- SQLite работает в WAL-режиме с `busy_timeout` и foreign keys на каждом соединении.
- Не кладите `SESSION_SECRET` и БД в одну резервную копию. Используйте secret manager или отдельный защищённый mount.
- На остановке бот отменяет и ожидает все отслеживаемые фоновые задачи.
- Для production добавьте внешний healthcheck, ротацию логов и мониторинг FloodWait/ошибок заказов.
